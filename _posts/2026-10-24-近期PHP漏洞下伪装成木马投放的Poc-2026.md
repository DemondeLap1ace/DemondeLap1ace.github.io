140009b57:   xor    dl,0x5a                 ; XOR 0x5A 还原

开头装入长度13，分配缓冲，指针/容量/长度三联写栈，RustVec<u8>布局，随后解密循环逐字节xor dl,0x5a还原，13 正是iphlpapi.dll十二个字符加结尾空字符的长度。

140009e84:   cmp    edx,r11d                  ; 与 USERNAME 哈希比

### ror13 批量反查

哈希反查的方法论是识别算法→确认规约→字典爆破，用Python现算：

```
python3 -c "
def ror13(s):
    h=0
    for c in s.lower().encode():
        h=((h>>13)|(h<<19))&0xFFFFFFFF; h=(h+c)&0xFFFFFFFF
    return h
print(hex(ror13('kernel32.dll')), hex(ror13('getadaptersinfo')))"



0x8fecd63f 0x7a120602
```

与样本中出现的两个立即数逐位相符，算法与规约双双确认，然后从8万行反汇编提取全部 mov ecx/edx, imm32立即数，用词表建反向索引批量反查：

python3 ror13_batch.py    # 正则 r"^\s*([0-9a-f]+):.*\bmov\s+(?:ecx|edx),0x([0-9a-f]{6,8})" 扫 disasm.txt

共提取立即数 116 个，词表 68 条，命中 51 个

三层构造：

锚点层，九个 DLL 名，验证算法用；证据驱动层，字符串层已证明的每项能力反推对应 API 家族，截屏推 GDI 链、中文双档提示推服务与注册表族、memexec.rs 推 Virtual 四连；变体层，A/W 后缀与Ex变形，词表质量取决于与样本证据的咬合度。

### 错误码分流的指令级闭环

ror13名单显示服务体系与注册表簇地址互相缠绕，取CreateServiceW解析点0x140013ce9与 RegCreateKeyExW解析点0x1400149e4各±40行窗口。

第一个窗口是典型的一次备齐全部弹药，六个服务管理API一口气解析完毕，每个失败都跳同一撤离点，然后才开第一枪OpenSCManagerW(NULL, NULL, 3)，权限位3=连接服务管理器加创建服务，第二个窗口揭示了双档切换的真实机制，比预想更讲究一点

```
call   CreateServiceW
   ...
   call   GetLastError
   cmp    eax,0x431                 ; 1073 = ERROR_SERVICE_EXISTS
   je     0x14001…                  ; → OpenServiceW(SERVICE_ALL_ACCESS=0xf01ff) 全权接管
   ...
   cmp    r13d,0x5                  ; 5 = ERROR_ACCESS_DENIED
   je     0x14001…                  ; → 落入注册表 Run 键路径
```

代码里没有任何我是不是admin的权限预检，先试装服务再取 GetLastError按错误码分流，服务已存在就用OpenServiceW以全权接管，安装器因此幂等，重复投放不露馅还顺手完成载荷更新；权限不足才落入注册表路径，写当前用户Run键。

这样不做权限预检就少调一串Token查询API，行为特征更小，先试高档，失败按错误码降级对受害者环境零假设，普通用户双击和管理员双击都能落地，ChangeServiceConfig2W暗示写服务描述伪装或配置失败自动重启，是驻留韧性加分项；幂等安装对"热点期批量投递、总会有人点两次"的场景是刚需。
